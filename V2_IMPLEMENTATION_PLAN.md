# News-Rust-bioinformation v2 Implementation Plan

> Generated according to `News-Rust-bioinformation v2 架构设计与实施规格.md` Section 74 (Step 2).

---

## 1. Current Architecture (v1)

### 1.1 Data Layer
- **`data/tools.yaml`**: Flat YAML sequence of 211 tool records. Each record has:
  `name`, `url`, `repo` (optional), `category` (flat slug matching hardcoded categories), `description`, optional `papers` (array of `{title, url}`), and optional `status: retired`.
- **`data/metadata.json`**: GitHub cache generated by GraphQL batches containing:
  `fetched_at`, `incomplete`, `urls`, and `repos: { [repo]: { stars, pushed_at, archived, latest_release_at, latest_release_tag, error } }`.
- **`data/snapshots/`**: Contains full copies of `metadata.json` named `YYYY-MM-DD.json` (weekly snapshots).
- **`data/config.yaml`**: Configuration for radar thresholds (`stale_months`, `cold_inactive_months`, `active` star delta / releases, `snapshots.keep`).

### 1.2 Code Layer (Rust CLI `nrb`)
- **`src/catalog.rs`**: Hardcoded static category tree (`CATEGORIES: &[Category]`), parsing and validation of v1 YAML documents, `Tool` and `Paper` structs, URL normalizations.
- **`src/metadata.rs`**: Loading/saving `metadata.json`, snapshot date sorting and pruning, sorting key `( -stars, -pushed_at, name )`, format meta suffix for README.
- **`src/fetch.rs`**: GraphQL batch query against GitHub API (`stargazerCount`, `pushedAt`, `isArchived`, `latestRelease`), dumps `metadata.json` and a snapshot.
- **`src/readme.rs`**: Generates `README.md` catalog by category with star counts and last push dates.
- **`src/radar.rs` / `src/radar_md.rs`**: Compares current snapshot with previous snapshot to find new entries, active entries (stars, releases, cold push), stale repos, and watch repos. Writes `RADAR.md`.
- **`src/digest.rs` / `src/discover.rs`**: Editorial outline generator and GitHub/bioRxiv candidate discovery.

### 1.3 Automation Layer
- `.github/workflows/lint.yml`: Validates YAML, runs `cargo test`, rebuilds README, runs lychee link check.
- `.github/workflows/weekly.yml`: Runs `fetch-metadata`, `build-readme`, `build-radar`, commits changes.
- `.github/workflows/discover.yml`: Manual candidate discovery.
- `.github/workflows/digest.yml`: Manual digest draft generator.

## 2. Schema Differences (v1 vs v2)

| Aspect | v1 Architecture | v2 Architecture Specification |
|---|---|---|
| **`tools.yaml` root** | Flat list `[ {name, ...}, ... ]` | Map `{ schema_version: 2, categories: {...}, tools: {...} }` |
| **Tool Identifier** | None (indexed by list order / URL) | Explicit unique key (slug e.g. `noodles`, `rust-bio`) |
| **Repository field** | Optional full or partial `repo: owner/name` | Standardized `repository: owner/name` (with fallback `url` if non-GitHub) |
| **Category model** | Single slug per tool (`category: bacterial-assembly`) | Defined in YAML header; tool has `category: { primary: "...", secondary: [...] }` |
| **Architecture** | None | `architecture: { rust_role, interfaces, foreign_dependencies }` |
| **Status** | Optional `status: retired` | Structured `status: { catalog: active \| retired \| watch \| excluded }` |
| **Learning** | None | `learning: { recommended: bool, level: ..., topics: [...] }` |
| **Publications** | List of `{ title, url }` | List of `{ doi: Option<String>, url: Option<String>, title: String, type: PublicationType }` |
| **Activity calculation** | Implicit in radar comparison only | Standardized badge in README & metadata (`🟢 Active`, `🟡 Maintained`, `🟠 Quiet`, `🔴 Inactive`, `⚫ Archived`) |
| **Badges in README** | Plain text `(★ 720, pushed 2026-08-31)` | Structured badges: `🦀 Native`, `🐍 Rust × Python`, `🔗 Binding`, `🟢 Active`, `★ 720`, `📖 Source Pick` |
| **Snapshot format** | Full clone of `metadata.json` | Compact `{ date, repositories: { [repo]: { stars, forks } } }` |
| **Trends** | Ad-hoc radar delta | Formal `data/trends.json` with 7d / 30d / 90d star growth and trending/emerging classification |
| **README Structure** | Single flat catalog | Header with stats, *At a Glance*, *Trending*, *Emerging*, *Source Code Picks*, *Catalog*, *Rust × Python*, *Retired*, *Methodology* |
| **JSON Schema** | None | `schema/tools.schema.json` and `schema/config.schema.json` |

## 3. Files to Modify and Create

### 3.1 New Schema & Data Files
- `schema/tools.schema.json`: JSON schema for `tools.yaml` v2 validation.
- `schema/config.schema.json`: JSON schema for `config.yaml` v2.
- `data/trends.json`: Generated trend metrics cache.
- `.github/ISSUE_TEMPLATE/add-tool.yml`: GitHub Issue form for community tool submissions.

### 3.2 Rust Codebase Refactoring
- **`src/model.rs` (New)**:
  - Strongly-typed Serde representations for v2 catalog, tools, categories, architecture, learning, publications, and status.
  - Rust enums: `RustRole` (`native`, `hybrid`, `binding`, `experimental`, `unknown`), `Interface` (`cli`, `library`, `python`, `r`, `web`, `workflow`, `api`, `wasm`), `LearningLevel` (`beginner`, `intermediate`, `advanced`), `CatalogStatus` (`active`, `retired`, `watch`, `excluded`), `PublicationType` (`journal`, `preprint`, `conference`, `software_paper`).
- **`src/config.rs` (Modify)**:
  - Update `Config` for `activity` thresholds, `emerging` thresholds, `trending` thresholds, and `readme` display limits.
- **`src/validate.rs` (New or Refactor `catalog.rs`)**:
  - Validates `schema_version == 2`, unique tool slugs, valid category paths, valid architecture and interfaces, valid DOIs and repository formats, required fields.
- **`src/migration.rs` (New)**:
  - Lossless migration tool `nrb migrate-v2` converting v1 list to v2 map while guaranteeing tool and publication counts are strictly conserved.
- **`src/metadata.rs` (Modify)**:
  - Support Metadata v2, compute activity levels (`Active`, `Maintained`, `Quiet`, `Inactive`, `Archived`), format architecture and activity badges.
- **`src/trends.rs` (New)**:
  - Calculates 7d / 30d / 90d star growth from snapshots; identifies Trending and Emerging projects.
- **`src/snapshot.rs` (New or refactor in `metadata.rs`)**:
  - Writes compact snapshots `{ date, repositories: { [repo]: { stars, forks } } }`.
- **`src/readme.rs` (Modify)**:
  - Deterministic renderer for README v2:
    - Overview metrics (`At a Glance`)
    - 🔥 Trending (top 30d star gainers)
    - 🌱 Emerging (new, active, <150 stars)
    - 📖 Recommended Source Code (curated from `learning`)
    - 🧬 Bioinformatics Applications (CRISPR, Microbial, etc.)
    - 🦀 Core Rust Libraries
    - 🐍 Rust × Python
    - ⚙️ Infrastructure & Workflows
    - 📊 Project Activity & Methodology
- **`src/radar.rs` / `src/radar_md.rs` (Modify)**:
  - Adapt to v2 data model, metadata, and trend signals.
- **`src/main.rs` (Modify)**:
  - Expose CLI subcommands:
    `validate`, `check`, `fetch-metadata`, `snapshot`, `trends`, `build-readme`, `build-radar`, `digest`, `discover`, `migrate-v2`.
- **`src/lib.rs` (Modify)**:
  - Re-export modules and types.

### 3.3 Workflows & Documentation
- `.github/workflows/validate.yml`: CI check with `cargo fmt --check`, `cargo clippy`, `cargo test`, `nrb check`.
- `.github/workflows/update-metadata.yml`: Daily metadata fetch + conditional commit.
- `.github/workflows/weekly-radar.yml`: Weekly snapshot + trends + radar + readme update.
- `CONTRIBUTING.md`: Update guidelines with v2 schema specifications and submission checklist.

## 4. Migration Risks & Mitigations

1. **Risk: Loss of Tool or Publication Data**
   - *Mitigation*: Pre-migration snapshot verifies 211 tools and 44 publications. Migration test asserts `v2_tools.len() == 211` and `v2_publications.len() == 44`.
2. **Risk: Hallucinating Architectures**
   - *Mitigation*: Strictly follow the rule in Section 60 & 75: default to `rust_role: unknown`, `foreign_dependencies: []`, and only tag known tools (e.g. `noodles`, `rust-htslib`, `sourmash`) where architecture is clear.
3. **Risk: Non-deterministic README Output**
   - *Mitigation*: Use ordered keys (`BTreeMap`) or deterministic sorting: `(category_order, -stars, -pushed_at, name)`. Output timestamps as date-only `YYYY-MM-DD` without hours/seconds.
4. **Risk: Breaking Existing CI During Transition**
   - *Mitigation*: Implement data models, schema validation, and unit tests before migrating production files. Maintain backwards-compatible loaders for existing metadata.json files.

## 5. Implementation Order

- **Phase 1: Foundation & Data Model**
  - Define `src/model.rs` and JSON Schema `schema/tools.schema.json`.
  - Implement validation logic and unit tests in `src/validate.rs`.
  - Build migration logic in `src/migration.rs` and test on existing `data/tools.yaml`.
- **Phase 2: Migration Execution**
  - Execute migration: transform `data/tools.yaml` to v2 schema.
  - Validate that exactly 211 tools and 44 publications are preserved.
  - Update `data/config.yaml` to v2 schema.
- **Phase 3: Metadata, Activity & Badges**
  - Enhance `src/metadata.rs` with activity status calculation and badge formatters (`🦀 Native`, `🐍 Rust × Python`, `🟢 Active`, etc.).
  - Update `src/fetch.rs` to support GitHub GraphQL v2 metadata extraction.
- **Phase 4: README v2 Deterministic Redesign**
  - Rewrite `src/readme.rs` to generate the new section layout with At a Glance stats, Trending, Emerging, Source Picks, and badged catalog.
  - Verify deterministic output.
- **Phase 5: Snapshots, Trends & Radar**
  - Implement compact snapshots in `src/snapshot.rs`.
  - Implement `src/trends.rs` and `data/trends.json` generation.
  - Update `src/radar.rs` and `src/radar_md.rs` to consume v2 data.
- **Phase 6: CLI & GitHub Actions Integration**
  - Wire up CLI commands in `src/main.rs`: `check`, `validate`, `snapshot`, `trends`, `build-readme`, `build-radar`, `fetch-metadata`.
  - Update `.github/workflows/` (`validate.yml`, `update-metadata.yml`, `weekly-radar.yml`).
  - Create `.github/ISSUE_TEMPLATE/add-tool.yml`.
  - Update `CONTRIBUTING.md`.
- **Phase 7: Verification & Acceptance**
  - Run `cargo fmt --check`, `cargo clippy`, `cargo test`.
  - Run `cargo run -- validate` and `cargo run -- build-readme`.
  - Generate `IMPLEMENTATION_SUMMARY.md`.
